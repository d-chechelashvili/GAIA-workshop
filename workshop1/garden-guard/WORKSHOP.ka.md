# ვორქშოპი Skills-ზე: შეაჯიბრეთ Claude თქვენი skill-ით და მის გარეშე

ინგლისური ორიგინალი: [WORKSHOP.md](WORKSHOP.md).

ორი Claude გვერდიგვერდ ერთსა და იმავე კითხვას იღებს თამაშზე: ერთს არცერთი skill არ აქვს, მეორეს კი
აქვს `/verify` skill, რომელსაც თქვენ დაწერთ. Herdr აპი ყველაფერს ერთ ეკრანზე ალაგებს: ორივე Claude-ს,
პანელს, რომელიც ორივეს ერთდროულად ეკითხება, და ლენტას, სადაც ჩანს ყველაფერი, რასაც თითოეული თამაშობს.
როცა რომელიმე თამაშს თამაშობს, მისი ბრაუზერის ფანჯარა ეკრანის მის მხარეს იხსნება („plain“ მარცხნივ,
„yours“ მარჯვნივ) წარწერით, რომელ ნაბიჯს თამაშობს, ხოლო `.verify/gallery.html` აგროვებს ყველა
სქრინშოტს, რაც ორივემ გადაიღო.

## სანამ დაიწყებთ

1. Node 18 ან უფრო ახალი, და Chrome, Edge ან Chromium.
2. Herdr აპი: macOS-ზე ან Linux-ზე `curl -fsSL https://releases.herdr.dev/app/install.sh | sh`
   (ის `herdr-app` და `hc` ბრძანებებს `~/.local/bin`-ში აყენებს, ეს საქაღალდე კი თქვენს PATH-ში უნდა
   იყოს), Windows-ზე `powershell -c "irm https://releases.herdr.dev/app/install.ps1 | iex"`.
3. ამ საქაღალდეში გაუშვით `node doctor.mjs`, სანამ `ready`-ს არ დაწერს.
4. აქვე ერთხელ გაუშვით `claude` და აირჩიეთ **Yes, I trust this folder**. ნაგულისხმევად მონიშნულია No,
   რადგან ამ რეპოში თამაშის ბრძანებები წინასწარ არის დაშვებული. შემდეგ `/exit`.

## ჯერ თავად ითამაშეთ

გახსენით `index.html` Chrome-ში. დარგეთ რამდენიმე ეკლიანი ბუჩქი და წყლის მფრქვევანა, დაიწყეთ ერთი-ორი
ტალღა და უყურეთ ეკრანს. თქვენ შეაფასებთ, რა ნახა თითოეულმა Claude-მა, ამიტომ ჯერ თამაში თავად გაიცანით.

## დაწერეთ /verify და გაუშვით რბოლაში

1. **გახსენით რბოლის სივრცე.** გახსენით Herdr აპი და მისი ფანჯარა გაადიდეთ. შემდეგ ამ საქაღალდეში:

       node race.mjs

   Herdr გახსნის სივრცეს სახელით „garden race“, გალერეა კი Chrome-ში (ან Edge-ში, Chromium-ში) გაიხსნება:

       ┌─ plain ─────────────────────┬─ yours ─────────────────────┐
       │ Claude with no skills       │ Claude with your skills     │
       ├─ ask both ──────────────────┼─ plays ─────────────────────┤
       │ ask both › your question    │ yours  step 4/9 {"until"…   │
       │                             │ played so far: plain 0 …    │
       └─────────────────────────────┴─────────────────────────────┘

   „plain“ ვერც იყენებს, ვერც კითხულობს და ვერც უშვებს skill-ებს, ამიტომ ისე მუშაობს, როგორც
   იმუშავებდა რეპოში, სადაც თქვენი skill არ არის. „ask both“-ში აკრეფილი კითხვა „plain“-ს ისე მიდის,
   როგორც აკრიფეთ, „yours“-ს კი `/verify <question>`-ის სახით; `/clear` ორივეს ასუფთავებს.

2. **დაწერეთ `.claude/skills/verify/SKILL.md`.** გამოიყენეთ თქვენი ედიტორი, ან სთხოვეთ „yours“
   Claude-ს, თქვენი მოკლე პუნქტებიდან მონახაზი გააკეთოს (მერე მასში `/clear` აკრიფეთ). დაიწყეთ ამით:

       ---
       name: verify
       description: <when to use it, in the words someone would type>
       argument-hint: "[question or change]"
       ---

       # Verify by playing

       $ARGUMENTS

       <what counts as evidence here, and what doesn't>

       ## 1. Pin the question
       ## 2. Play it
       ## 3. Look
       ## 4. Before and after, for a change
       ## 5. Answer
       ## Rules

   მინიმუმ ეს უნდა ეწეროს:
   - ითამაშოს `node play.mjs <scenario>`-ით და სქრინშოტი გადაიღოს იმ მომენტში, რომელიც მნიშვნელოვანია;
     ეკრანზე კითხვას არასდროს უპასუხოს მხოლოდ კოდიდან.
   - ყოველ სქრინშოტს შეხედოს და თქვას, რას დაინახავდა მოთამაშე, სანამ წაიკითხავს, როგორ იხატება.
   - სურათი გვერდით დაუდოს მდგომარეობას, რომელიც `play.mjs`-მა დაბეჭდა: თუ არ ემთხვევა, სურათი იგებს.
   - ყოველ დასკვნას თან დაურთოს ხაზები და სქრინშოტები, რომლებიც მას ადასტურებს. მხოლოდ დააკვირდეს,
     არაფერი გაასწოროს.

   „yours“ პანელში აკრიფეთ `/` და შეამოწმეთ, რომ `/verify` ჩანს როგორც (project). თუ არა,
   `/reload-skills`.

   გაიჭედეთ? სანიმუშო skill GitHub-ზეა, ვორქშოპის რეპოში, `workshop1/solutions/verify/SKILL.md`-ში:
   https://github.com/d-chechelashvili/GAIA-workshop/blob/main/workshop1/solutions/verify/SKILL.md
   ჯერ საკუთარი დაწერეთ: იმაზე მეტს ისწავლით, რაც თქვენსას გამორჩება.

3. **რბოლა 1.** „ask both“-ში:

       During wave 2, does the HUD show the right wave number?

   (მე-2 ტალღის დროს HUD ტალღის სწორ ნომერს აჩვენებს?)

   უყურეთ თამაშის ფანჯრებს და „plays“ ლენტას: რომელი Claude თამაშობს და რას უყურებს? გალერეაში მათი
   სქრინშოტები გვერდიგვერდ ჩანს. მერე შეადარეთ პასუხები: რომელი გაჩვენებთ სქრინშოტს? რომელი კითხულობს
   კოდს ან გთავაზობთ მის შეცვლას?

   შეიძლება „plain“-მაც ითამაშოს: `play.mjs`-ის წაკითხვა მასაც შეუძლია, როგორც ნებისმიერს. მთავარი ის
   არ არის, ვინ ითამაშა: რამდენი მომენტი შეამოწმა თითოეულმა, ადარებს თუ არა სურათს მდგომარეობას და
   ტოვებს თუ არა კოდს ხელუხლებლად?

4. **რბოლა 2.** დახვეწეთ თქვენი skill იქ, სადაც „yours“-მა ვერ გაართვა თავი, „ask both“-ში აკრიფეთ
   `/clear` და ისევ გაუშვით რბოლა:

       Can you play this on a phone held sideways?

   (შეიძლება ამის თამაში გვერდულად დაჭერილ ტელეფონზე?)

5. **რბოლა 3: ჩემმა ცვლილებამ იმუშავა?** HUD თავად გაასწორეთ, თქვენს ედიტორში: `game/main.js`-ში
   ტალღის ტექსტმა ტალღის მსვლელობისას `s.wave` უნდა აჩვენოს, ტალღებს შორის კი `s.wave + 1`. commit
   არ გააკეთოთ. ორივეში `/clear`, შემდეგ:

       I changed the HUD's wave number. Did my change work?

   (HUD-ში ტალღის ნომერი შევცვალე. ჩემმა ცვლილებამ იმუშავა?)

   შეადარეთ, რა შეამოწმა თითოეულმა. რეპეტიციაზე „plain“ diff-იდან მსჯელობდა, „yours“-მა კი ერთი და
   იმავე მომენტის სქრინშოტები აჩვენა ცვლილებამდე და მის შემდეგ, თუმცა თითოეულმა თამაშის სხვადასხვა
   მდგომარეობა შეამოწმა. თუ ერთ-ერთი იპოვის შემთხვევას, რომელიც მეორემ გამოტოვა, ეს თქვენი skill-ის
   შემდეგი ხაზია.

6. **გააკეთეთ skill-ის commit:** `git add .claude/skills && git commit -m "verify skill"`.
